# Batch 3: Search, Knowledge Graph, and Security/Compliance features

Nine features spanning LLM-powered search, knowledge graph visualization, document comparison, OCR scoring, compliance reporting, geo-fencing, watermarking, access request workflow, and session recording. The implementation follows established patterns in the codebase (service classes, Pydantic schemas, admin role checks) and lands ~5600 lines across 51 files with comprehensive test coverage. Watch for: the geo-fence middleware fails open on any exception (confirmed), the access request approval workflow doesn't actually grant permission to the resource (confirmed), session recording is wired up as a helper but never called from document access endpoints (confirmed), and the PDF watermark overlay is a no-op due to incomplete pikepdf page composition (confirmed).

## High-level view

The geo-fence middleware evaluates IP/country rules from the database on every request when enabled, but swallows all exceptions and allows the request through. This fail-open design is explicitly coded (the `except Exception` block logs and continues), which is a deliberate availability-over-security trade-off worth flagging for production review.

The access request workflow creates requests, sends notifications, and allows admins to approve or deny, but approval only flips a status field in the `access_requests` table. No permission grant or group membership is actually conferred, making the approval action a record-keeping exercise rather than a functional access control change.

Session recording provides a `record_access` fire-and-forget helper, but it is never imported or called from the document API endpoints. The sessions table will remain empty in production unless integrated.

The watermark service handles images correctly via Pillow compositing, but the PDF watermark path creates a watermark image, converts it to a single-page PDF, opens it with pikepdf, then hits a `pass` statement where the overlay should be applied. The output PDF is the original with no watermark.

The knowledge graph builds an in-memory graph from documents, groups, keywords, and relationships with no pagination or size cap, which becomes a problem at scale.

Comparative analysis truncates each document to 4000 characters before sending to the LLM but doesn't communicate this limitation in the API response.

<details>
<summary>Issues (7)</summary>

1. **Geo-fence fails open on exception** — The middleware catches all exceptions and allows the request. If the database is unreachable or rules fail to parse, geo-fencing is silently bypassed. Consider failing closed (403) for security-critical deployments, or at minimum alerting on bypass.
2. **PDF watermark is a no-op** — `apply_pdf_watermark` creates the watermark image and PDF but the overlay logic has a `pass` placeholder. The returned bytes are the unmodified source PDF. Implement the pikepdf page content stream merge or switch to a reportlab-based overlay.
3. **Access request approval doesn't grant access** — `approve_request` sets status to "approved" but never adds a group membership, document permission, or any ACL entry. The approval is cosmetic.
4. **Session recording never called** — `record_access` exists but is not invoked from any document view/download endpoint. Sessions will never be populated in normal operation.
5. **Knowledge graph loads all documents without pagination** — `build_graph` fetches all matching documents and relationships in memory. With large document sets, this could produce oversized responses and slow queries. Add a limit or streaming mechanism.
6. **Geo-fence rule evaluation ignores scope for middleware calls** — The middleware calls `evaluate_rules(db, ip, country)` without passing `resource_type` or `resource_id`, so document- and group-scoped rules are skipped. Only global rules take effect at the middleware level.
7. **Watermark text template injection** — `render_text` uses Python `str.format()` with user-controlled `custom_text`. If `custom_text` contains format specifiers like `{__class__}`, it could leak internal state or raise exceptions. Use a safer substitution method.

## Geo-fence middleware: fail-open posture and scope gap

The middleware in `app/middleware/geofence.py` wraps the entire rule evaluation in a blanket `except Exception` that logs the error and calls `call_next(request)`. Any database connectivity issue, malformed rule JSON, or unexpected `ipaddress` parsing failure results in the request being allowed through without any security alert being logged (the alert logging is inside the `try` block, before the `except`).

```python
except Exception as e:
    # If geo-fence check fails, log but allow the request through
    logger.error(f"Geo-fence check failed: {e}")
```

The scope gap compounds this: `evaluate_rules` accepts optional `resource_type` and `resource_id` parameters for fine-grained document/group rules, but the middleware never passes these:

```python
if rule.scope == "document" and resource_type == "document":
    if rule.scope_id is not None and rule.scope_id != resource_id:
        continue
elif rule.scope == "group" and resource_type == "group":
    ...
elif rule.scope != "global":
    if rule.scope != "global":
        continue
```

When `resource_type` is `None` (the middleware case), document and group rules are skipped via the final `elif` branch. The admin API for rule creation doesn't communicate this limitation, so an admin creating a document-scoped deny rule would expect it to work but it won't block anything at the middleware level.

Country detection relies entirely on the `X-Country-Code` header, which is trivially spoofable unless set by a trusted upstream proxy that strips client-provided values.

## PDF watermark: incomplete overlay

`WatermarkService.apply_pdf_watermark` builds a watermark image, converts it to a single-page PDF via Pillow's PDF export, then opens it with pikepdf. But the actual overlay step is:

```python
if "/Contents" in page_obj:
    # Add watermark as an overlay using form XObject
    pass  # Simple approach: just save with annotations
```

The `pass` means the watermark PDF is opened and immediately closed, the original page is unmodified, and `pdf.save(output)` returns the original document bytes. Image watermarking works correctly via Pillow alpha compositing, so only PDFs are affected.

## Access request workflow: approval without effect

`AccessRequestService.approve_request` updates the `status` field to "approved" and records who reviewed it, but performs no side effect that would actually grant the requester access. The feature spec calls for "grants permission (for groups: could add a GroupMembership or note; for documents: log the grant)" but neither is implemented. The admin would need to separately grant the actual permission through another mechanism.

## Session recording: wired but unconnected

`app/services/session_recording.py` provides `record_access()` as a top-level helper designed to be called from document endpoints:

```python
async def record_access(db, user_id, document_id, action, ip_address=None, user_agent=None):
```

`app/api/documents.py` does not import or call this function. The sessions API (`GET /api/sessions`) will work but will always return empty results until integration is added. The test suite tests the service and API in isolation, so this gap isn't caught by tests.

## Natural language search: silent truncation in comparative analysis

Comparative analysis truncates each document to 4000 characters before sending to the LLM (`content[:4000]`), which is a reasonable budget control but isn't communicated in the API response. A user comparing long documents won't know the analysis is based on truncated content. Adding a field like `truncated: true` or `characters_analyzed: 4000` to the response would make this transparent.

## Knowledge graph: unbounded query

`KnowledgeGraphService.build_graph` issues an unfiltered `select(Document)` when no filters are provided, loading all documents in the system into memory. The entity fallback path has a similar issue — when `entity` is specified but no documents matched filters, it loads *all* documents to scan keywords:

```python
if entity and not documents:
    all_docs_result = await db.execute(select(Document))
    all_docs = all_docs_result.scalars().all()
```

For a production system with thousands of documents, this produces unbounded memory pressure and response sizes. The vis.js frontend would also struggle to render.

## Watermark template text injection

`WatermarkService.render_text` substitutes variables using Python's `str.format()`:

```python
return template.format(user=user, timestamp=timestamp, doc_id=doc_id, custom_text=custom_text)
```

The current API doesn't expose `custom_text` as a user parameter (it's hardcoded to empty string), and templates are set by admins, so this is a latent risk rather than an exploitable issue today. If `custom_text` becomes user-supplied in future, format specifiers like `{0}` or `{custom_text.__class__}` could leak internal state or raise exceptions. Consider switching to `string.Template` or manual `str.replace()`.

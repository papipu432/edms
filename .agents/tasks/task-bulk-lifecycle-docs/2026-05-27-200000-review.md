# Bulk operations, document lifecycle state machine, and security hardening for EDMS

This change adds three feature clusters to the EDMS application: bulk document operations (batch upload with auto-folder creation, bulk workflow actions), a document lifecycle state machine (Draft through Expired with recurring review cycles, email notifications, alerts API), and a full organizational RBAC replacement (UUID users, permissions, LDAP, envelope encryption, ransomware detection, backup management). It also adds 11 documentation files. The diff spans 100 files with ~14,700 new lines across application code, services, templates, tests, and docs.

Watch for:
- **Bulk upload partial failure leaves committed documents** — if file 3 of 5 fails, files 1-2 are already flushed to the DB with no rollback, and their background pipelines are already scheduled (confirmed).
- **No authorization on lifecycle read endpoints** — `GET /api/documents/{id}/lifecycle`, `GET .../history`, and `GET /api/lifecycle/alerts` require no authentication, exposing lifecycle metadata to anonymous callers (confirmed).
- **Lifecycle `expired` state is a terminal sink** — no transition defined out of `expired`, so a document that expires can never re-enter the lifecycle without manual DB intervention (confirmed).
- **Email notifications always send to self** — `check_and_send_alerts` sends every alert to `SMTP_FROM_EMAIL` rather than the assigned reviewer or document owner (confirmed).

## High-level view

The bulk operations layer adds a `BulkService` that iterates files sequentially within a single DB session. Each file is flushed individually, so a failure mid-batch produces a partially-committed set of documents with no transactional boundary around the full batch. A new `sign_off` workflow action is wired into the permission map alongside the existing approve/reject/request_changes actions.

The lifecycle state machine defines six states with a transition map enforced at the service layer. Transitions are audited via `LifecycleTransition` records. The recurring lifecycle type sets `next_review_at` when transitioning to `up_to_date`, but the `expired` state has no outgoing transitions — once a document expires, the only path back is to delete the lifecycle and recreate it. The alerts API finds documents approaching expiry or review deadlines but the endpoint is unauthenticated.

The RBAC overhaul replaces the old enum-based `RoleName` with a data-driven `Role` model keyed by `code`. User primary keys change from integer to UUID strings, propagating through all FK references (workflow entries, annotations, folder assignments). Permission checks short-circuit for the `admin` role via a hard-coded bypass in every guard factory.

The security features (envelope encryption, Shamir Secret Sharing, ransomware detection, backup management) add significant surface area. The KEK is generated and persisted to disk encrypted with a passphrase, but no code loads it into the `StorageService` at startup — encryption remains opt-in per-call. Registration is gated behind `ALLOW_REGISTRATION` (defaults to `True`). The placeholder token in `chroma_config/token.txt` is documented as needing replacement but remains committed.

8. **Runtime-only settings mutation** — Backup, LLM, and security config changes via API mutate the `settings` singleton without persistence. A restart silently reverts all changes with no user-facing warning in the API response.

## Bulk upload transactional semantics

In `app/services/bulk.py`, the `bulk_upload` method iterates over files and calls `db.flush()` after each document creation:

```python
for file in files:
    ...
    db.add(document)
    await db.flush()
    await db.refresh(document)
    background_tasks.add_task(_run_pipeline, document.id, ...)
    results.append(BulkUploadResult(document_id=document.id, ...))
```

If file 4 of 5 raises an exception, documents 1-3 are already flushed and their pipeline background tasks are already enqueued. The `except Exception` block catches the error and adds a failure result, but does not roll back the already-flushed documents. When the request handler's `get_db` dependency commits at the end, documents 1-3 are persisted permanently.

The background pipelines for committed documents will run even if the caller interprets the partial failure as a reason to retry the entire batch. There's no way to cancel or undo the committed subset via the API — a retry produces duplicates.

## Unauthenticated lifecycle endpoints

The lifecycle router in `app/api/lifecycle.py` protects mutation endpoints (`create_lifecycle`, `transition_lifecycle`, `check_alerts`) with `Depends(get_current_user)` or `Depends(require_role("admin"))`. However, the read endpoints have no auth dependency:

```python
@router.get("/api/documents/{document_id}/lifecycle", ...)
async def get_lifecycle(document_id: int, db: AsyncSession = Depends(get_db)):
    ...

@router.get("/api/documents/{document_id}/lifecycle/history", ...)
async def get_lifecycle_history(document_id: int, db: AsyncSession = Depends(get_db)):
    ...

@router.get("/api/lifecycle/alerts", ...)
async def get_lifecycle_alerts(days_before_expiry: int = 30, ...):
    ...
```

The alerts endpoint is particularly sensitive — it returns document names, IDs, expiry dates, and review schedules for all documents in the system without any access control.

## Lifecycle state machine terminal state

The `VALID_TRANSITIONS` map defines:

```
draft -> in_review
in_review -> approved | draft
approved -> up_to_date
up_to_date -> needs_re_review | expired
needs_re_review -> in_review | expired
```

The `expired` state has no entry in the map, meaning `self.VALID_TRANSITIONS.get(current_state, [])` returns `[]`. A document that reaches `expired` — either from `up_to_date` or `needs_re_review` — cannot be transitioned to any other state. For a document management system where expired documents might need reactivation after updates, this creates a dead end that requires database manipulation to resolve.

## Email notification target resolution

In `app/services/email_notifications.py`:

```python
async def check_and_send_alerts(self, db: AsyncSession) -> int:
    ...
    for alert in alerts:
        self.send_lifecycle_alert(
            to_email=self.from_email,  # <-- always sends to system email
            ...
        )
```

The `DocumentLifecycle` model has an `assigned_reviewer_id` field specifically for this purpose, but the notification service never queries the reviewer's email. Every alert goes to the system's `SMTP_FROM_EMAIL` address regardless of who is responsible for the document.

## Decrypted content in temp files during read

`StorageService.read_from_data` decrypts to a `NamedTemporaryFile` on disk before reading into memory:

```python
with tempfile.NamedTemporaryFile(delete=False) as tmp:
    tmp_path = Path(tmp.name)
try:
    EnvelopeEncryption.decrypt_file(file_path, tmp_path, effective_kek)
    return tmp_path.read_bytes()
finally:
    tmp_path.unlink(missing_ok=True)
```

If the process crashes between `decrypt_file` and `unlink`, plaintext remains on disk. The `encrypt_file` path has the same pattern in reverse. Supporting in-memory decryption in `EnvelopeEncryption` would eliminate this exposure window.

## Bulk workflow action role validation ordering

In `app/api/bulk.py`, the `/workflow` endpoint uses `Depends(get_current_user)` rather than a role-gated dependency:

```python
@router.post("/workflow", response_model=BulkActionResponse)
async def bulk_workflow_action(
    data: BulkActionRequest,
    current_user: User = Depends(get_current_user),
    ...
):
    action = WorkflowAction(data.action)  # may raise ValueError -> 400
    allowed_roles = _ACTION_ALLOWED_ROLES.get(action, [])
    ...
```

The role check happens after action parsing. If the action string is invalid, the user gets a 400 regardless of their roles. The shorthand endpoints (`/approve`, `/signoff`) correctly use `role_required(["approver", "admin"])`. The inconsistency means the generic `/workflow` endpoint lets authenticated users with no relevant roles probe for valid action strings (they see 400 for invalid vs 403 for valid-but-unauthorized).

# Bulk operations, lifecycle state machine, and documentation (v2)

The four issues flagged in v1 have been addressed: lifecycle read endpoints now require authentication (GET lifecycle and history require `get_current_user`, GET alerts requires `require_role("admin")`), the `expired` state has an outgoing transition to `draft`, email notifications resolve the reviewer's email from the User model via `assigned_reviewer_id`, and the `BulkUploadResponse` schema documents partial-commit semantics in its docstring.

Watch for:
- **Synchronous SMTP inside async handler** — `send_lifecycle_alert` uses blocking `smtplib.SMTP` directly in the async `check_and_send_alerts` coroutine, which blocks the event loop for every alert (confirmed).
- **Email fallback silently sends to system address** — when no `assigned_reviewer_id` is set or the reviewer has no email, the alert goes to `SMTP_FROM_EMAIL` with no indication to the caller that the intended recipient wasn't reached (confirmed).
- **No test coverage for EmailNotificationService** — the reviewer-email resolution logic and SMTP fallback path have zero unit or integration tests (confirmed).

## High-level view

The email notification service now queries the lifecycle record and resolves the reviewer user, but does so synchronously on the event loop via `smtplib.SMTP`. For a batch of many alerts this serializes multiple network round-trips on the main thread. The fallback behavior — sending to `SMTP_FROM_EMAIL` when no reviewer is assigned — means that documents without an `assigned_reviewer_id` generate alerts that arrive at a system mailbox with no differentiation from properly-routed alerts.

The `check_and_send_alerts` method's reviewer-resolution logic — the core fix for v1 issue #4 — has no test coverage. The lifecycle auth tests are thorough (four tests covering 401/403 scenarios), but the email service remains verified only by inspection.

## Synchronous SMTP in async context

`check_and_send_alerts` is an async method that iterates over alerts and calls `self.send_lifecycle_alert(...)` for each one. That method opens a synchronous TCP connection via `smtplib.SMTP`:

```python
with smtplib.SMTP(self.smtp_host, self.smtp_port) as server:
    if self.smtp_user and self.smtp_password:
        server.starttls()
        server.login(self.smtp_user, self.smtp_password)
    server.send_message(msg)
```

Each call blocks the asyncio event loop for the duration of the TCP handshake, TLS negotiation, and SMTP exchange. With 50 documents approaching expiry, this serializes 50 blocking network operations on the thread that should be serving HTTP requests. The endpoint is admin-only (`POST /api/lifecycle/check-alerts`), so the blast radius is limited to admin sessions, but a slow or unreachable SMTP server will stall the request for `N * timeout` seconds.

Wrapping `send_lifecycle_alert` in `asyncio.to_thread()` is a one-line fix that moves the blocking I/O off the event loop.

## Email fallback semantics

The reviewer resolution logic:

```python
to_email = self.from_email
lifecycle = await db.get(DocumentLifecycle, lifecycle_id)
if lifecycle and lifecycle.assigned_reviewer_id:
    reviewer = await db.get(User, lifecycle.assigned_reviewer_id)
    if reviewer and reviewer.email:
        to_email = reviewer.email
```

Three distinct conditions fall through to the `self.from_email` default: no lifecycle found (shouldn't happen given the query), no `assigned_reviewer_id` set on the lifecycle, or the reviewer user has no email. The latter two are operationally meaningful but produce no log output distinguishing them from a properly-routed alert. The `count` return value also doesn't differentiate — a caller seeing `alerts_sent: 10` has no way to know that 7 went to a system mailbox because reviewers weren't assigned.

## Untested email notification paths

The email notification service has no test coverage. The `check_and_send_alerts` method's reviewer-resolution logic — the core fix for v1 issue #4 — is verified only by code inspection, not by a test that exercises the path with an assigned reviewer vs. a missing one. A regression test mocking SMTP and verifying the `to_email` argument would prevent silent reversion.

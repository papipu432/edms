# Security hardening and org RBAC integration for EDMS

This change replaces the simple user/role model with a full organizational RBAC system (UUID-based users, fine-grained permissions, org hierarchy, LDAP sync), adds encrypted storage with AES-256-GCM envelope encryption and Shamir Secret Sharing key recovery, introduces ransomware detection via filesystem monitoring, and adds settings pages for LLM provider selection, backup management, and encryption key lifecycle. It also hardens the ChromaDB deployment with Docker Compose security options. The diff spans 76 files and roughly 7,400 new lines across six features.

Watch for:
- **LDAP injection** in `authenticate_ldap` — user-controlled input is interpolated directly into an LDAP search filter without escaping (confirmed).
- **Missing permission seeds** — `settings:manage` and `security:manage` are enforced in endpoint guards but never seeded in the permission table, making those endpoints admin-only by implicit bypass rather than explicit policy (confirmed).
- **Session cookie missing `secure` and `samesite` flags** — the cookie is `httponly` but will transmit over HTTP and is vulnerable to CSRF (confirmed).
- **Open user registration** — `/api/auth/register` has no auth guard, allowing unauthenticated account creation (confirmed).

## High-level view

The RBAC integration replaces the old enum-based `RoleName` with a code-based `Role` model and a many-to-many `UserRole` junction table, making permissions data-driven. Permission checks short-circuit for the admin role via a hard-coded `"admin" in user_roles` bypass in every guard. This makes the system workable but means the `settings:manage` and `security:manage` permissions exist only as strings in guards — non-admin users can never be granted them because they're not in the seed data.

The envelope encryption is correctly implemented: per-file DEKs wrapped by a single KEK using AES-256-GCM, with the wrapped DEK stored in the encrypted file header. However, the KEK is only loaded into the `StorageService` if explicitly passed at construction time — there's no lifecycle that loads the KEK from the encrypted key store on startup, so encryption is opt-in per-call rather than automatic.

The Shamir Secret Sharing implementation over GF(256) is mathematically sound — polynomial evaluation via Horner's method, Lagrange interpolation for reconstruction, proper validation of thresholds and duplicate indices. The `/api/settings/encryption/init` endpoint returns share material in the HTTP response body, which is the only time shares are visible; they're not persisted in the database.

The session cookie auth works by falling back to a `access_token` cookie when no Bearer header is present. The cookie is set `httponly` but lacks `secure=True` and `samesite` attributes, and no CSRF protection exists for the form-based login path.

The ransomware detector runs a watchdog observer thread and fires alerts when filesystem ops/sec exceeds a configurable threshold. Alerts are stored in-memory in the detector singleton; the wiring to persist them in `SecurityAlert` is stubbed out (the `_persist_alert` callback in `start_monitor` is a no-op).

The ChromaDB Docker Compose adds token auth, read-only filesystem, no-new-privileges, and localhost-only port binding. The checked-in `token.txt` contains the placeholder `change-me-to-a-secure-token`, which will fail-open if deployed without modification.

<summary>Details</summary>

## LDAP filter injection in authenticate_ldap

In `app/services/ldap_service.py` line 218:

```python
search_filter=f"({config.attr_username}={username})",
```

The `username` parameter arrives from user input in the login form. An attacker can supply a value like `*)(|(objectClass=*` to modify the search semantics. The same pattern appears in `run_sync` but with admin-controlled data. The `authenticate_ldap` path is reachable from user-submitted credentials, making it the exploitable vector. The fix is to call `ldap3.utils.conv.escape_filter_chars(username)` before interpolation.

## Permission seed gap for settings and security endpoints

The `PERMISSIONS` list in `app/main.py` seeds only: `users`, `roles`, `org_units`, `org_positions`, `org_grades`, `org_assignments`, `documents`, `ldap`, `reports`, `audit`. The LLM, backup, and security endpoints all guard with `require_permission("settings", "manage")` or `require_permission("security", "manage")`. Because `require_permission` short-circuits for admin (`"admin" in user_roles`), the admin user passes, but no other role can ever receive these permissions — they aren't in the database to be assigned via `RolePermission`.

This means the system works for admin-only access today, but the moment someone tries to delegate settings management to a non-admin role (e.g., a "settings_manager" role), they will hit a 403 with no way to resolve it without a code change.

## Session cookie security attributes

In `app/api/auth.py`:

```python
response.set_cookie(key="access_token", value=access_token, httponly=True)
```

Missing: `secure=True` (cookie transmits only over HTTPS), `samesite="lax"` or `"strict"` (prevents CSRF via cross-origin form submissions). The `httponly` flag alone prevents JavaScript access but does not address network interception or cross-site request forgery. The `POST /auth/login` form endpoint also has no CSRF token mechanism.

## Open registration allows unauthenticated account creation

The `/api/auth/register` endpoint has no dependency on `get_current_user` or any auth guard. Any network client can create a new user with any email. In a document management system with RBAC, this is a privilege escalation vector — while newly created users have no roles, they exist in the user table and could be assigned roles by LDAP sync or admin oversight.

## Ransomware alert persistence stub

In `app/api/security.py`, the `start_monitor` endpoint defines:

```python
async def _persist_alert(alert_data: dict):
    """This is called from the detector thread - we just store for now."""
    pass
```

This callback is defined but never even set on the detector (the `detector.set_alert_callback(...)` call is missing). Alerts generated by the detector live only in `self._alerts` (a list on the singleton instance). On process restart or detector reset, all alert history is lost.

## KEK lifecycle gap in StorageService

The `StorageService` constructor accepts an optional `kek` parameter, and `save_to_data`/`read_from_data` use it. But no code in `app/main.py` lifespan or elsewhere loads the KEK from the encrypted key store (`<storage>/.keys/kek.enc`) and passes it to the `StorageService` instances used by the pipeline. The pipeline's `StorageService()` call in `app/services/pipeline.py` uses no KEK, so documents processed through the pipeline are stored unencrypted regardless of whether encryption is initialized.

## Decrypted content in temp files

`StorageService.read_from_data` decrypts to a temp file, reads it into memory, then deletes it:

```python
with tempfile.NamedTemporaryFile(delete=False) as tmp:
    tmp_path = Path(tmp.name)
try:
    EnvelopeEncryption.decrypt_file(file_path, tmp_path, effective_kek)
    return tmp_path.read_bytes()
finally:
    tmp_path.unlink(missing_ok=True)
```

If the process crashes between `decrypt_file` and `unlink`, plaintext remains on disk. For the decryption path, decrypting directly to a `BytesIO` buffer (modifying `EnvelopeEncryption` to support in-memory decryption) would avoid this exposure.

## Runtime-only config mutation

The LLM and backup settings endpoints mutate the `settings` singleton directly:

```python
settings.LLM_PROVIDER = config.llm_provider
settings.MINIO_PRIMARY_ENDPOINT = config.minio_primary_endpoint
```

These changes are lost on restart. This is documented as intentional in the feature findings, but there's no indication in the API response or UI that changes are ephemeral. Combined with the fact that `pydantic-settings` `BaseSettings` objects are nominally frozen (though this implementation doesn't set `frozen=True`), this pattern is fragile — a future `model_config` update adding `frozen=True` would break these endpoints silently.

# Security and robustness hardening pass (v2)

This commit addresses five of the seven issues raised in the v1 review: path traversal in the wiki page reader, a startup warning for the default encryption password, context truncation in both the wiki query and RAG chat paths, and `top_k` validation on the search schema. The remaining two (no authentication, blocking LLM calls) were acknowledged as acceptable trade-offs for an MVP prototype. All 82 tests pass, including two new path traversal tests.

**Watch for:** mid-truncation data corruption in RAG context (possible), and the encryption password warning being a log-only guard with no enforcement (confirmed but accepted per MVP scope).

**Verdict**: APPROVED

## High-level view

The path traversal fix uses `Path.resolve().is_relative_to()` — the standard Python 3.9+ idiom for containment checks — and is exercised by two new tests covering both simple (`../`) and nested (`entities/../../`) traversal vectors.

The context truncation in both wiki query (100k chars) and RAG chat (50k chars) uses a hard character slice. This prevents token-limit API errors, which was the primary risk. Slicing mid-document can split a chunk mid-sentence, creating a minor inconsistency between what the LLM sees and what the `sources` list returns to the client.

The `top_k` validation adds `Field(ge=1, le=20)` to `SearchRequest`. The chat endpoint hardcodes `top_k=5` internally and never exposed it to user input, so both paths are now bounded.

The encryption password fix adds a `logger.warning()` at startup when the default `"changeme"` value is detected — a soft guard that still allows the application to start.

## Context truncation trade-offs

Both truncation points slice raw characters without regard to document or chunk boundaries:

```python
# wiki.py — 100k chars
if len(wiki_context) > max_context_size:
    wiki_context = wiki_context[:max_context_size]

# search.py — 50k chars
if len(context) > max_context_size:
    context = context[:max_context_size]
```

For the RAG chat path specifically, truncation happens after the `sources` list is already populated with full chunk text. If the slice cuts mid-chunk, the model's answer may not reference material that appears in the sources response. A future improvement would be to truncate by dropping trailing chunks entirely (and removing them from `sources`) rather than slicing characters.

The asymmetry in limits (100k for wiki, 50k for chat) reflects that chat context competes with conversation history for the context window.

## Path traversal fix

The check runs before the existence check, so non-existent traversal paths are also rejected without leaking timing information about file existence outside the wiki root. Both `resolve()` calls handle symlink canonicalization, preventing escape via symlinked directories inside the wiki tree.

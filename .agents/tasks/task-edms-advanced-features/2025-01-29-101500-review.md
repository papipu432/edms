# Advanced features: error handling, prompt guard, audit trail, versioning, preview, comparison, security monitoring (v2)

This change adds seven cross-cutting features to the EDMS: structured error responses with request tracing, anti-prompt-injection filtering, an append-only document audit trail, per-version DEK-encrypted document versioning, preview generation, a document comparison service, and a security monitoring layer. Each feature ships as a self-contained service + API router pair. The v1 review surfaced 8 issues; all have been addressed in this revision.

**Watch for:** The exception-handling architecture still has a subtle redundancy between middleware and registered handlers that can produce double-logging on unhandled errors (likely). A committed placeholder token in `chroma_config/token.txt` will trip secret-scanning tools in CI (confirmed).

**Verdict**: APPROVED

## High-level view

All eight v1 concerns are resolved. The versioning service deletes plaintext after encryption and narrows the catch to `(ValueError, OSError, KeyError, NotImplementedError)`. The audit model uses `ondelete="SET NULL"` with nullable `document_id`. The webhook endpoint returns 403 when no secret is configured. Both rate limiters document their per-process limitation in module docstrings. The middleware no longer duplicates `EDMSBaseError` handling. The preview converter validates link schemes via `_safe_link`. The document history endpoint requires `audit:read`.

Two minor concerns remain: a cosmetic double-logging path in the error handler middleware, and a placeholder token committed to source control.

## Exception handling architecture overlap

`RequestIDMiddleware.dispatch` catches generic `Exception` and converts to a 500 response. Separately, `register_exception_handlers` installs handlers for `EDMSBaseError` (with correct status codes) and generic `Exception`. Because `BaseHTTPMiddleware`'s `call_next` wraps the inner ASGI app, FastAPI's registered handlers fire first — the middleware's catch only activates for errors during response streaming or in other middleware layers.

The v1 duplication (middleware explicitly catching `EDMSBaseError`) is gone. The remaining overlap: both paths log at ERROR with similar messages. If a streaming error fires the middleware path, the log line is nearly identical to what the registered handler produces, making triage harder. A `"[middleware-fallback]"` prefix would disambiguate.

## Versioning encryption cleanup

`create_version` calls `file_path.unlink()` after `EnvelopeEncryption.encrypt_file` succeeds but before the database flush. If the flush fails, an orphaned ciphertext file remains on disk — but since the wrapped DEK lives in the not-yet-committed version record, the ciphertext is effectively unrecoverable. This is the correct trade-off over leaking plaintext.

## Preview XSS mitigation

The `_safe_link` method:

```python
if href_stripped.startswith(("http://", "https://")) or (
    ":" not in href_stripped.split("/")[0]
    and not href_stripped.startswith("//")
):
    return f'<a href="{href}">{text}</a>'
return text
```

Blocks `javascript:`, `data:`, `vbscript:`, and protocol-relative URLs. A theoretical bypass via tab characters in scheme names (`java\tscript:`) is neutralized because the regex operates on already-escaped text where `<` and `>` are entities.

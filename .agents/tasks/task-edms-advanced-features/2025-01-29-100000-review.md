# Advanced features: error handling, prompt guard, audit trail, versioning, preview, comparison, security monitoring

This change adds seven cross-cutting features to the EDMS: structured error responses with request tracing, anti-prompt-injection filtering on all LLM calls, an append-only document audit trail, per-version DEK-encrypted document versioning, preview generation (PDF/image/markdown), a document comparison service, and a security monitoring layer with config generators and KMS rate limiting. The approach is additive — each feature ships as a self-contained service + API router pair wired through `app/api/router.py` — and integrates with the existing permission system. Test coverage is substantial (20+ new test files).

**Watch for:** plaintext version files retained on disk after encryption succeeds (confirmed); audit log deletion via CASCADE when documents are removed, defeating immutability (confirmed); in-memory rate limiter state lost on restart or multi-process deployment (confirmed); versioning silently swallows all encryption failures with a bare `except Exception` (confirmed).

## High-level view

The error handling layer installs a `RequestIDMiddleware` that catches both custom `EDMSBaseError` subclasses and unhandled exceptions, attaching a UUID to every response. A token-bucket-style rate limiter (in-memory, per-IP) sits above it. Both depend on single-process state, so horizontal scaling will require a shared store.

Prompt injection defense wraps all user content in `<user_content>` XML tags, prepends a "data-only" instruction, and strips known injection patterns via regex before any LLM call. The patterns are reasonable for surface-level attacks; they won't stop prompt-boundary confusion in complex multi-turn contexts, but provide a baseline.

The audit trail records document actions (upload, view, download, delete) into an immutable-by-convention `DocumentAuditLog` table. The table's foreign key uses `ondelete="CASCADE"`, which contradicts the immutability claim — deleting a document removes its entire audit history from the database.

Document versioning generates a new AES-256-GCM Data Encryption Key per version, wraps it via the KMS, and stores the encrypted file alongside the plaintext original. The plaintext file is never removed after successful encryption, leaving unencrypted content on disk.

Preview generation dispatches on file type: PyMuPDF for PDFs, Pillow for images, and a hand-rolled regex-based markdown-to-HTML converter. Cached previews go to `data/previews/`. The markdown converter does not sanitize against XSS beyond basic entity escaping.

The comparison service uses Python's `difflib` to produce unified diffs and side-by-side HTML. For version comparisons it reads version storage paths directly as markdown, which works only for text-based versions stored unencrypted.

Security monitoring provides static config generators (auditd, falco, suricata rules as strings), a KMS rate limiter (in-memory sliding window per IP), and a webhook ingestion endpoint for external alerts. The webhook validates a shared secret via an `X-Webhook-Secret` header, but an empty `SECURITY_MONITORING_WEBHOOK_SECRET` setting causes the validation to be skipped entirely, making the endpoint unprotected by default.

<summary>Issues (8)</summary>

1. **Plaintext version files not deleted after encryption** — `VersioningService.create_version` writes the raw file to disk, then encrypts to a `.enc` path, but never removes the original plaintext file. Delete `file_path` after `EnvelopeEncryption.encrypt_file` succeeds.
2. **Audit log CASCADE deletes history** — `DocumentAuditLog.document_id` uses `ondelete="CASCADE"`. Change to `SET NULL` or remove the FK constraint to preserve audit records after document deletion.
3. **Bare except in versioning swallows all errors** — The `except Exception` block in `create_version` catches every failure (including `MemoryError`, `SystemExit` subtypes). Narrow to specific exceptions (`KMSError`, `EncryptionError`) and re-raise unexpected ones.
4. **Webhook endpoint unprotected when secret is empty** — In `ingest_monitoring_alert`, `if settings.SECURITY_MONITORING_WEBHOOK_SECRET:` skips validation entirely when the env var is unset. Default to rejecting requests when no secret is configured.
5. **In-memory rate limiters reset on restart** — Both `RateLimiterMiddleware` and `KMSRateLimiter` use per-process dicts. Under multi-worker (gunicorn) or restart scenarios, limits are not enforced. Document this limitation or switch to Redis-backed counters.
6. **Duplicate exception handling in RequestIDMiddleware and exception handlers** — Both the middleware's `dispatch` and `register_exception_handlers` catch `EDMSBaseError`. The middleware catches it first, so the registered handlers are unreachable for EDMS errors. Remove one path.
7. **Preview markdown converter does not prevent stored XSS** — The markdown-to-HTML converter escapes `<`, `>`, `&` but then re-introduces raw HTML via regex replacements (e.g., `<a href=...>`). If markdown contains attacker-controlled link targets, the generated HTML can carry XSS payloads (e.g., `javascript:` URLs in the `href`).
8. **Document history endpoint exposes audit to any authenticated user** — `get_document_history` uses `get_current_user` (any valid login), while `get_recent_activity` requires `audit:read` permission. A non-privileged user can view the full audit trail of any document by ID.

## Plaintext remnant in versioning encryption

`VersioningService.create_version` (lines 60-100) writes user-uploaded content to `file_path` before attempting encryption:

```python
file_path.write_bytes(file_content)
# ... later:
EnvelopeEncryption.encrypt_file(file_path, enc_path, dek)
encrypted_path = f"versions/{document_id}/{enc_filename}"
```

After encryption succeeds, `file_path` still exists on disk with the unencrypted content. The DEK is generated fresh per version and wrapped correctly, but the security benefit is nullified because the plaintext sits next to the ciphertext. A `file_path.unlink()` after successful encryption is needed. The `except Exception` fallback path intentionally keeps the plaintext, which is fine for that branch, but the happy path must clean up.

The same block catches every conceivable exception type including `KeyboardInterrupt` and `SystemExit` via bare `except Exception`. This should be narrowed to the KMS/encryption error types introduced in this same changeset (`KMSError`, `EncryptionError`, `ValueError`).

## Audit trail immutability undermined by CASCADE

The `DocumentAuditLog` model declares:

```python
document_id: Mapped[int] = mapped_column(
    Integer, ForeignKey("documents.id", ondelete="CASCADE"), ...
)
```

When a document is deleted (via `DELETE /api/documents/{id}`), the database cascades the delete to all audit entries. The feature's stated purpose — immutable audit trail — is incompatible with this. The test suite even acknowledges this with a comment: "With CASCADE, the audit entry is deleted when document is deleted." Changing to `ondelete="SET NULL"` (and making `document_id` nullable) or removing the FK constraint preserves history while still allowing document cleanup. An `archived_document_id` or soft-delete pattern would be more robust.

## Webhook secret bypass

```python
if settings.SECURITY_MONITORING_WEBHOOK_SECRET:
    if x_webhook_secret != settings.SECURITY_MONITORING_WEBHOOK_SECRET:
        return {"status": "error", "message": "Invalid webhook secret"}
```

When `SECURITY_MONITORING_WEBHOOK_SECRET` is empty (the default), the outer `if` is falsy and validation is skipped entirely. Any caller with a valid user token can inject arbitrary security alerts into the system. The fix is to reject requests when no secret is configured, or to require the secret to be non-empty in production via a startup check.

## Rate limiter single-process limitation

`RateLimiterMiddleware` stores request timestamps in a `defaultdict(list)` scoped to the middleware instance. In multi-worker deployments (uvicorn with `--workers N`, gunicorn), each worker has independent state. An attacker can cycle through workers to bypass limits. The `KMSRateLimiter` has the same architecture. This is acceptable for single-process deployments but should be documented prominently or gated behind a feature flag that disables the middleware when a distributed backend isn't configured.

## Duplicate exception-handling paths

`RequestIDMiddleware.dispatch` catches `EDMSBaseError` exceptions directly in its try/except block and converts them to JSON responses. Separately, `register_exception_handlers` registers a FastAPI exception handler for the same `EDMSBaseError` base class. Because Starlette's `BaseHTTPMiddleware` wraps the ASGI app, exceptions raised in route handlers are caught by the middleware before reaching FastAPI's exception-handler machinery. The registered handlers will only fire for errors raised _after_ the middleware's `call_next` returns (which doesn't happen for route-level exceptions). This dead code adds confusion without value — remove one path.

## Preview XSS vector via markdown link targets

The markdown-to-HTML preview converter escapes angle brackets early, then applies regex-based link conversion:

```python
body = re.sub(
    r"\[(.+?)\]\((.+?)\)",
    r'<a href="\2">\1</a>',
    body,
)
```

If a document's markdown content contains `[click](javascript:alert(1))`, the resulting HTML serves the `javascript:` URL in a directly-renderable `<a>` tag. Since previews are served as `HTMLResponse`, this is a stored XSS vector. The link `href` should be validated to allow only `http://`, `https://`, and relative paths.

## Document history authorization gap

`get_document_history` is protected only by `get_current_user` — any authenticated user can query `/api/documents/{id}/history` for any document. In contrast, `get_recent_activity` correctly requires `audit:read`. A user without document access can enumerate actions, actor usernames, and IP addresses for documents they shouldn't see. Either gate history behind the same `audit:read` permission, or verify the caller has `documents:read` access to the specific document.

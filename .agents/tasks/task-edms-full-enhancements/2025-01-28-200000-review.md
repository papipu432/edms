# Eight-feature expansion: KMS, setup wizard, relationships, health monitor, Obsidian export, enhanced search, persistent chat, WebSocket notifications

This change adds eight major subsystems to the EDMS in a single branch push (~8,000 new lines). A pluggable KMS abstraction layer backs KEK wrapping for both production and a newly isolated backup KEK. A first-time setup wizard (CLI + web) bootstraps the entire system from scratch. Document relationships introduce a cross-reference graph with transitive dependency traversal. A health monitor detects orphaned lifecycles, broken reviewers, stale documents, and empty groups. Obsidian vault export converts wiki pages to wikilink format with Dataview-compatible frontmatter. Enhanced search adds faceted filtering, autocomplete suggestions, related documents via vector similarity, and per-user search history. Chat gains persistent sessions with multi-turn context, scoped RAG, and markdown export. Real-time notifications arrive via WebSocket with a REST layer for history and read tracking.

**Watch for:** setup wizard web endpoint writes `.env` to the filesystem and generates KEK shares without any authentication gate beyond the `is_first_launch()` check, creating a race window on first boot (confirmed); the WebSocket auth accepts the JWT via query-string parameter, exposing tokens in server access logs and browser history (confirmed); keyword filtering in faceted search uses raw string interpolation in a SQL `LIKE` clause, opening a SQL wildcard injection vector (confirmed); the `NotificationManager` is an in-process singleton that does not survive multi-worker deployments or restarts (confirmed); health monitor `detect_broken_reviewers` issues N+1 queries per lifecycle row (confirmed).

## High-level view

The KMS layer provides a `KMSProvider` ABC with a working `LocalFileKMS` (scrypt + AES-GCM wrapping) and two stub providers (Vault, Cosmian). The backup KEK manager isolates backup encryption from the production key hierarchy using per-operation DEKs, though Python's memory model makes DEK zeroization best-effort.

The setup wizard's web endpoint accepts configuration without authentication, relying solely on `is_first_launch()`. Between the moment a fresh instance starts and an operator completes setup, any network-reachable client can POST credentials and receive the KEK shares.

Document relationships use a standard adjacency model. The transitive dependency resolver is a BFS that issues one DB query per node visited, which will not scale for deeply connected document sets.

The health monitor's `detect_broken_reviewers` and `detect_empty_groups` checks both exhibit N+1 query patterns that will degrade with data growth.

Obsidian export endpoints mount with no authentication dependencies, exposing the full wiki vault to any client.

The keyword filter in faceted search constructs a `LIKE` pattern by embedding user input directly (`f"%{kw}%"`), allowing SQL wildcard characters to manipulate query selectivity.

Persistent chat sends full conversation history to the LLM every turn with no truncation or windowing. The document-scoped RAG search filters globally-retrieved results post-hoc, missing relevant chunks if they aren't in the global top-K.

The WebSocket notification system uses a process-local singleton with no cross-worker fanout, and authenticates via JWT in the query string, leaking tokens to infrastructure logs.

1. **Setup wizard unauthenticated race** — `POST /api/setup/configure` has no auth; any client can configure the system and receive KEK shares between first boot and setup completion. Add a time-limited setup token or bind the endpoint to localhost only. (confirmed)

Characters `%` and `_` act as wildcards, and on some backends `\` can escape. Escape special LIKE characters before interpolation. (confirmed)
4. **NotificationManager single-process only** — The singleton holds WebSocket references in a process-local dict. Multi-worker deployments (uvicorn `--workers N`, Gunicorn) will miss notifications for users connected to other workers. Document the single-process constraint or add a pub/sub backend (Redis, pg LISTEN/NOTIFY). (confirmed)
5. **N+1 queries in broken reviewer detection** — `detect_broken_reviewers` calls `await db.get(User, ...)` once per lifecycle row. Batch-load all distinct reviewer IDs in a single query. (confirmed)
6. **Unbounded chat context window** — `send_message` sends the full message history to the LLM every turn with no truncation. Long sessions will hit token limits and produce errors or silent truncation. Add a sliding window or token-budget check. (likely)
7. **Obsidian export endpoints lack authentication** — The `/api/wiki/export/obsidian` routes have no `Depends(get_current_user)` or role check. Any unauthenticated client can export the entire wiki vault. (confirmed)

9. **Default KMS passphrase is a static string** — `KMS_LOCAL_PASSPHRASE` defaults to `"changeme-kms-passphrase"` in config. ## Setup wizard and the unauthenticated configuration window

The web setup wizard guards its endpoints with `is_first_launch()`, which returns `True` when `.env` is missing or contains default placeholders. The `POST /api/setup/configure` endpoint trusts the JSON body to provide database URLs, admin credentials, SMTP credentials, MinIO keys, and LLM API keys — then writes them to `.env` and returns KEK shares in the response body.

```python
@router.post("/api/setup/configure")
async def configure_system(request: Request):
    if not is_first_launch():
        return JSONResponse(status_code=400, ...)
    data = await request.json()
    # ... writes .env, returns KEK shares
```

Between application startup and the moment an operator completes setup, the endpoint is open to any network client. A container exposed on port 8000 with no reverse proxy would accept configuration from the first requestor. The KEK shares — the most sensitive output of the entire encryption hierarchy — are returned to whoever wins that race.

## WebSocket authentication via query-string JWT

```python
@router.websocket("/ws/notifications")
async def websocket_notifications(websocket: WebSocket, token: str = Query(...)):
    username = _verify_ws_token(token)
```

Query parameters appear in HTTP access logs (nginx, ALB, CloudFront), are stored in browser history, and may be cached by CDN edge nodes. For long-lived tokens (the default `ACCESS_TOKEN_EXPIRE_MINUTES` is 30 minutes), this creates a significant exposure window.

The endpoint calls `websocket.accept()` before verifying user existence in the database, meaning the WS upgrade completes before auth is fully verified. If the user lookup fails, the already-accepted connection is closed — a minor but observable auth-before-accept ordering issue.

## SQL wildcard injection in faceted keyword search

```python
if request.keywords:
    for kw in request.keywords:
        query = query.where(
            func.cast(Document.keywords, SAString()).like(f"%{kw}%")
        )
```

A user supplying `keywords: ["%"]` would match every document regardless of actual keywords. More subtly, `_` matches any single character, so `keywords: ["___"]` matches any document with a 3+ character keyword entry. This isn't a traditional SQL injection (the value is parameterized by SQLAlchemy), but it allows semantic manipulation of the query's selectivity.

## Notification system architecture constraints

`NotificationManager` stores WebSocket references in `self._connections: dict[str, list[WebSocket]]`. With uvicorn's `--workers 4`, a user connecting to worker 2 will never receive notifications emitted by worker 3.

The `mark_notification_read` endpoint has an authorization gap:

```python
if notification.user_id is not None and notification.user_id != current_user.id:
    return {"detail": "Not authorized"}
```

This returns a 200 OK with an error body. A client checking `response.status_code == 200` will believe the operation succeeded. This should raise `HTTPException(status_code=403)`.

## Chat context window and scoped RAG

The chat service builds the full conversation history for every LLM call:

```python
messages_for_llm = []
for msg in all_messages:
    messages_for_llm.append({"role": msg.role, "content": msg.content})
```

With no windowing, a session with 50 exchanges (each containing RAG context in the assistant replies) could easily reach 100k+ tokens. For OpenAI models with 4k-16k context windows, this will error on the API call. For Ollama models, it will degrade response quality.

The scoped RAG search for document-scoped sessions fetches results globally and filters post-hoc:

```python
if session.scope_type == "document" and session.scope_id is not None:
    results = [r for r in results if r["doc_id"] == session.scope_id]
```

The vector search retrieves 5 results globally, then discards those not from the target document. If the target document's chunks aren't in the top-5 globally similar results, the scoped chat returns no context despite relevant content existing. The fix is to pass a `where` filter to ChromaDB's query to constrain results to `doc_id` upfront.

## Health monitor query patterns

```python
for lifecycle, document in result.all():
    reviewer = await db.get(User, lifecycle.assigned_reviewer_id)
```

With 1,000 lifecycles assigned to 50 distinct reviewers, this issues 1,000 queries instead of 1. Collect distinct `assigned_reviewer_id` values, batch-load users in a single `SELECT ... WHERE id IN (...)`, then iterate.

`detect_empty_groups` has the same N+1 shape: one `SELECT ... LIMIT 1` per group to check for documents. A single query with `LEFT JOIN` and `GROUP BY` would replace it.

## Obsidian export unauthenticated endpoints

```python
router = APIRouter(prefix="/api/wiki/export/obsidian", tags=["obsidian"])

@router.get("")
async def export_obsidian_vault():
    zip_buffer = export_service.create_vault_zip()
    return StreamingResponse(zip_buffer, ...)
```

All three endpoints (`/`, `/sync`, `/page/{path}`) expose wiki content without any `Depends(get_current_user)`. Adding `current_user: User = Depends(get_current_user)` to each endpoint would close this.

## Backup KEK: DEK zeroization limitation

The DEK is generated as a `bytearray`, used for encryption, then zeroized in a `finally` block:

```python
dek = bytearray(get_random_bytes(KEY_SIZE))
try:
    dek_cipher = AES.new(kek, AES.MODE_GCM, ...)
    data_cipher = AES.new(bytes(dek), AES.MODE_GCM, ...)
    ...
finally:
    for i in range(len(dek)):
        dek[i] = 0
```

The `bytes(dek)` copy created for `AES.new()` is immutable and remains in memory until garbage collected. This is an inherent Python limitation, not a code defect — but any security audit of this path should note that the plaintext DEK may persist in the process heap beyond the `finally` block.

The key ID is derived from `sha256(wrapped_blob)[:16]`, which changes each time the same KEK is re-wrapped (wrapping is non-deterministic due to random salt/nonce). The same logical backup KEK will have different IDs if unwrapped and re-wrapped, which could complicate key rotation tracking.

All eight issues from the v1 review have been addressed. The activity feed now gates on `require_permission("audit", "read")`. Smart folder endpoints verify `folder.owner_id != current_user.id` and return 404 for mismatches. DocumentTag carries a `UniqueConstraint("document_id", "tag_id")` and the pipeline checks before inserting. Both command palette and smart folder LIKE queries use `_escape_like()` with `escape="\\"`. ## High-level view

The one remaining gap is in citation detection. The auto-tagging block was given a check-before-insert pattern to prevent duplicate `DocumentTag` rows, but the citation block immediately below it was not given the same treatment. On first processing this is fine; on re-processing, inserting a duplicate `(source_document_id, target_document_id, relationship_type=cites)` row hits the `uq_source_target_type` constraint, raises an `IntegrityError` during `flush()`, and leaves the async session in a failed-transaction state. The outer `except` catches it, but subsequent operations (preview generation, final commit) run on a poisoned session — marking the document as `failed` even though all processing actually succeeded.

## Citation detection lacks duplicate guard

The auto-tagging step correctly checks for existing associations before inserting:

```python
existing_link = await db.execute(
    select(DocumentTag).where(
        DocumentTag.document_id == doc_id,
        DocumentTag.tag_id == tag.id,
    )
)
if existing_link.scalar_one_or_none() is None:
    doc_tag = DocumentTag(document_id=doc_id, tag_id=tag.id)
    db.add(doc_tag)
```

The citation detection step, sitting directly below, skips this guard:

```python
for target_id in cited_ids:
    relationship = DocumentRelationship(
        source_document_id=doc_id,
        target_document_id=target_id,
        relationship_type=RelationshipType.cites,
    )
    db.add(relationship)
await db.flush()
```

`DocumentRelationship` has `UniqueConstraint("source_document_id", "target_document_id", "relationship_type")`. On re-processing (version upload, manual re-run), `flush()` raises `IntegrityError`. The `except Exception as cite_err` block catches it and logs a warning, but after a failed `flush()` the session transaction is in an aborted state. The subsequent preview generation step and the final `document.status = DocumentStatus.processed; await db.commit()` will both fail — the outer except then marks the document as `failed`.

The fix is to mirror the auto-tagging pattern: check for an existing relationship before inserting, or delete all `cites` relationships for `doc_id` at the top of the block before re-inserting.

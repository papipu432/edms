## Citation duplicate guard verified

The fix (lines 217–232 of `pipeline.py` in the diff) is structurally identical to the auto-tagging guard (lines 169–178):

```python
# Citation detection check-before-insert
for target_id in cited_ids:
    existing = await db.execute(
        select(DocumentRelationship).where(
            DocumentRelationship.source_document_id == doc_id,
            DocumentRelationship.target_document_id == target_id,
            DocumentRelationship.relationship_type == RelationshipType.cites,
        )
    )
    if existing.scalar_one_or_none() is None:
        relationship = DocumentRelationship(
            source_document_id=doc_id,
            target_document_id=target_id,
            relationship_type=RelationshipType.cites,
        )
        db.add(relationship)
await db.flush()
```

The `where` clause covers all three columns of the `uq_source_target_type` constraint on `DocumentRelationship`, so the check is complete — no partial match that could still allow a constraint violation. The `flush()` sits outside the loop, batching inserts for efficiency while the per-iteration guard ensures no duplicates reach the session.
